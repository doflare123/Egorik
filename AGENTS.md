# AGENTS.md

Инструкции распространяются на весь репозиторий Egorik.

## Цель проекта

Egorik — настольный голосовой ассистент с приоритетом безопасных и
детерминированных команд. Сначала запрос обрабатывают локальные команды и
сценарии. Только если они не подошли, запрос может перейти в ИИ-планировщик.

Главный принцип проекта:

> Модель предлагает план, но никогда не получает прямой доступ к системе.

Не превращайте приложение в универсального автономного агента. Любое действие
должно проходить через явно зарегистрированный локальный контракт с проверяемыми
аргументами.

## Технологии

- C# и .NET 10;
- Avalonia 12, MVVM без дополнительного MVVM-фреймворка;
- `Microsoft.Extensions.DependencyInjection` для композиции приложения;
- Vosk и NAudio для локального распознавания речи;
- Sherpa-ONNX/Piper для локального нейросинтеза речи;
- системный TTS Windows как резервный;
- MSTest для автоматических тестов;
- JSON-файлы в `%LocalAppData%\Egorik` для пользовательских настроек.

Версии NuGet-пакетов задаются централизованно в
`Directory.Packages.props`. Не указывайте версию непосредственно в `.csproj`.

## Границы проектов

### `src/Egorik.Core`

Содержит бизнес-правила и контракты, не зависящие от UI и конкретной ОС:

- `AssistantEngine` и порядок маршрутизации;
- контракты и маршрутизатор базовых команд;
- сценарии;
- настройки;
- контракты платформы, голоса, ИИ и плагинов;
- локальную проверку и последовательное исполнение ИИ-плана.

Core не должен ссылаться на Avalonia, Windows API, Vosk, Sherpa-ONNX, файловую
систему конкретной ОС или сетевой SDK провайдера.

### `src/Egorik.Infrastructure`

Содержит реализации контрактов Core:

- базовые команды;
- Windows/desktop-адаптеры;
- JSON-хранилища;
- Vosk STT и Sherpa/Piper TTS;
- OpenAI-compatible ИИ-планировщик;
- встроенные безопасные ИИ-инструменты.

Платформенную логику держите за интерфейсами из Core. Это необходимо для будущей
поддержки Linux и macOS.

### `src/Egorik.App`

Содержит Avalonia UI, ViewModel, жизненный цикл приложения и DI-композицию.
Регистрация новых реализаций выполняется в `Bootstrapper.cs`. Не переносите
бизнес-правила в code-behind или ViewModel.

### `tests/Egorik.Core.Tests`

Содержит модульные и интеграционные тесты безопасной логики. Тесты не должны
открывать реальные приложения, браузер, микрофон или внешнее API. Используйте
заглушки интерфейсов и тестовые `HttpMessageHandler`.

## Порядок обработки запроса

Не меняйте этот порядок без отдельного архитектурного решения:

1. Нормализация текста и удаление wake name.
2. Пользовательский сценарий.
3. Детерминированная базовая команда.
4. ИИ-планировщик, только если он настроен и базовая команда не найдена.
5. Локальная валидация всего ИИ-плана.
6. Последовательное выполнение разрешённых инструментов с остановкой при первой
   ошибке.

ИИ не должен перехватывать запросы, которые уже понимает базовый маршрутизатор.

## Правила безопасности ИИ

Ответ провайдера всегда считается недоверенным, даже при `strict: true` и
принудительном `tool_choice`.

- Модель возвращает только вызов `submit_plan` с упорядоченным массивом шагов.
- Перед первым действием валидируется весь план.
- Максимум — восемь шагов.
- Исполняются только зарегистрированные `IAiTool` с `CommandRisk.Low`.
- ID инструмента, набор аргументов, обязательность, длина и allowlist значений
  проверяются локально.
- Лишний или неизвестный аргумент отклоняет план.
- При ошибке шага оставшаяся часть плана не выполняется.
- Внешний endpoint должен использовать HTTPS. HTTP допустим только для loopback.
- API-ключ нельзя писать в `settings.json`, лог или текст ошибки. На Windows он
  хранится через DPAPI; переменная `EGORIK_AI_API_KEY` имеет приоритет.

Не добавляйте ИИ-инструменты для произвольного shell/PowerShell, запуска любого
пути, записи или удаления файлов, изменения реестра, установки программ,
произвольного HTTP-запроса либо URL. Для новой возможности создавайте узкий
инструмент с минимальным набором типизированных аргументов и явным allowlist.

Промпт и JSON Schema улучшают надёжность формата, но не являются границей
безопасности. Граница безопасности — `AiToolExecutor` и реализации инструментов.

## Добавление базовой команды

1. Реализуйте `IAssistantCommand` в `Egorik.Infrastructure/Commands`.
2. Дайте команде стабильный уникальный `CommandDescriptor.Id`.
3. Сопоставляйте только нормализованный текст и возвращайте осмысленную
   confidence.
4. Не выполняйте побочные действия в `MatchAsync`.
5. Исполняйте действие только в `ExecuteAsync` через платформенный интерфейс.
6. Пробрасывайте `CancellationToken`.
7. Зарегистрируйте команду в `Bootstrapper.cs`.
8. Добавьте тесты распознавания, ложных срабатываний и результата выполнения.

Избегайте слишком общих совпадений: маршрутизатор выбирает команду с наибольшей
confidence, поэтому широкое правило способно перехватить несвязанные фразы.

## Добавление ИИ-инструмента

1. Реализуйте `IAiTool`.
2. Используйте стабильный `snake_case` ID.
3. Опишите каждый аргумент через `AiToolParameterDescriptor`.
4. Задайте минимальный разумный `MaxLength` и `AllowedValues`, где это возможно.
5. Повторно проверяйте аргументы внутри `ExecuteAsync`; не полагайтесь только на
   общую проверку исполнителя.
6. Работайте через существующий платформенный интерфейс или добавьте узкий
   интерфейс в Core.
7. Зарегистрируйте инструмент в `Bootstrapper.cs`.
8. Добавьте тесты успешного плана и отклонения неизвестных, лишних и запрещённых
   значений.

Если инструмент нельзя честно классифицировать как низкорисковый, не подключайте
его к автоматическому ИИ-исполнению. Сначала нужен отдельный механизм подтверждения
пользователем.

## Голосовой контур

- Распознавание и синтез по умолчанию должны работать локально.
- Большие модели скачиваются только по явному действию пользователя.
- Не загружайте одну и ту же STT/TTS-модель повторно и не держите лишние копии в
  памяти.
- Освобождайте аудиоустройства, потоки, модели и нативные ресурсы при остановке.
- Не блокируйте UI-поток загрузкой модели, записью или синтезом.
- Поддерживайте отмену долгих операций.
- Сохраняйте резервный системный TTS, если нейроголос недоступен.
- Нечёткое распознавание применяется только к имени ассистента в начале фразы.
  Не расширяйте его на команды: это создаёт опасные ложные срабатывания.
- Не записывайте сырой звук без отдельной функции и явного согласия пользователя.

При изменении голосового контура проверяйте не только корректность, но и память:
после остановки прослушивания нативная модель и аудиоресурсы должны быть доступны
для освобождения.

## UI и настройки

- Пользовательские тексты интерфейса и голосовые ответы пишутся на русском языке.
- Долгие операции показывают состояние и не замораживают окно.
- Крестик главного окна должен скрывать приложение в tray, если пользователь явно
  не выбрал полный выход.
- Новое поле настройки добавляется в `AssistantSettings`, получает безопасное
  значение по умолчанию, корректно загружается из старого JSON и сохраняется через
  `IAssistantSettingsService`.
- Секреты не являются обычными настройками и хранятся отдельно.
- Не удаляйте и не перезаписывайте пользовательские приложения, сайты, сценарии и
  модели при миграции настроек.

Пользовательские данные находятся в `%LocalAppData%\Egorik`:

- `settings.json` — обычные настройки;
- `scenarios.json` — сценарии;
- `ai-api-key.dat` — защищённый ключ;
- `logs/` — диагностические журналы.

Тесты хранилищ должны использовать временный корневой каталог через
`ApplicationDataPaths`, а не реальные пользовательские данные.

## Плагины

Сейчас в Core существует только `IAssistantPlugin` и `PluginManifest`. Полноценный
загрузчик сторонних сборок, проверка совместимости, изоляция и выдача разрешений
ещё не реализованы.

До появления такой подсистемы:

- не загружайте произвольные DLL из пользовательской папки;
- не считайте поле `Permissions` реальной песочницей;
- не предоставляйте плагину service provider, shell или необработанные системные
  API;
- проектируйте плагины вокруг тех же узких контрактов команд и инструментов;
- для опасных разрешений потребуется явное подтверждение и отдельная платформа
  контроля доступа.

## Стиль кода

- Nullable reference types включены, предупреждения считаются ошибками.
- Используйте file-scoped namespaces и существующий стиль C#.
- Предпочитайте неизменяемые records для контрактов и DTO.
- Все асинхронные операции принимают и пробрасывают `CancellationToken`.
- Для часто синхронно завершающихся контрактов сохраняйте принятый в проекте
  `ValueTask`.
- Не используйте service locator; зависимости передаются через конструктор.
- Не создавайте глобальное изменяемое состояние.
- Не проглатывайте исключения без понятного пользовательского сообщения и
  диагностического контекста.
- Не редактируйте `bin/`, `obj/` и сгенерированные Avalonia-файлы.
- Делайте минимальные изменения и не форматируйте несвязанные файлы.

## Проверка изменений

Базовые команды из корня репозитория:

```powershell
dotnet restore Egorik.slnx
dotnet build Egorik.slnx --no-restore
dotnet test Egorik.slnx --no-restore
dotnet format Egorik.slnx --verify-no-changes --no-restore
```

После изменения UI дополнительно запускайте приложение:

```powershell
dotnet run --project src/Egorik.App/Egorik.App.csproj
```

Для изменений, зависящих от Windows, выполняйте ручную проверку соответствующей
функции. Автоматические тесты всё равно должны проверять независимую от ОС логику
через интерфейсы и заглушки.

## Критерии готовности

Перед завершением задачи убедитесь, что:

- сохранён порядок «базовые команды → ИИ fallback»;
- модель не получила новый прямой путь к системе;
- новые зависимости направлены от App/Infrastructure к Core, а не наоборот;
- миграция настроек не уничтожает пользовательские данные;
- отмена и освобождение ресурсов учтены;
- добавлены регрессионные тесты;
- решение собирается без предупреждений;
- все тесты проходят;
- документация обновлена, если изменилась настройка или поведение пользователя.
