# Вычисления через настроенный ИИ

По явному запросу пользователя вычисления, включая простую арифметику,
передаются ИИ-планировщику, если он включён и настроен. `CalculatorCommand`
в этом режиме не объявляет совпадение. Сам `AssistantEngine` сохраняет порядок:
нормализация → сценарий → базовая команда → ИИ → проверка плана → исполнение.

Это узкое исключение для калькулятора. Пользовательские сценарии и остальные
базовые команды, включая поиск, сохраняют приоритет. «Найди решение примера»
открывает обычный поиск; «посчитай пример» направляется планировщику. При
отключённом или ненастроенном ИИ арифметика вычисляется локально, как раньше.

Для простой арифметики планировщику предписано выбирать локальный `calculator`.
Для сложной математики используется текстовый `assistant_reply`; ответ модели
не считается проверенным точным результатом. При недоступном провайдере
пользователь получает ошибку, а не молчаливое переключение режима.

Для текущей погоды добавлен низкорисковый `get_weather`. Он принимает только
название города либо использует `DefaultWeatherCity`, по умолчанию Калининград.
Сервис обращается исключительно к двум фиксированным HTTPS endpoint Open-Meteo,
проверяет координаты, единицы, диапазоны значений, размер ответа и время расчёта.
Модель не выбирает URL и не получает прямой сетевой или системный доступ.
Ответ содержит фактические данные сервиса, источник и время. Для других текущих
числовых данных без отдельного инструмента промпт требует сообщить невозможность
проверки, а не придумывать значение.

Весь ИИ-план по-прежнему проверяется до первого действия; разрешены только
зарегистрированные низкорисковые инструменты и их документированные аргументы.
