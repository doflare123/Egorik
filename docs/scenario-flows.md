# Блок-схемы сценариев: экспериментальный API v1

Редактор находится во вкладке **Сценарии** и работает как конструктор
сцепляемых блоков. Выберите сохранённый сценарий в верхнем списке или нажмите
**Новый**, задайте название и фразу запуска. Рабочее поле занимает основную часть
окна. Кнопка **Развернуть** переключает окно в развёрнутый режим.

Перетащите действие, паузу, условие или текстовую команду из палитры слева
к подсвеченному стыку. Уже добавленные блоки перетаскиваются за заголовок.
Порядок и связи обновляются автоматически. Условие имеет две полости:
**если … то** и **иначе**. Вложите блоки в нужную полость; вложенное условие
перемещается вместе с содержимым. Старт и завершение не удаляются.
Перетаскивание стартовой шапки или фона сдвигает весь вид сценария.

Двойной щелчок по блоку, кнопка **···** или **Параметры** открывают окно настройки.
Поля строятся по контракту действия: списки допустимых значений, текст, числа
и логические значения. Постоянной правой колонки и ручного выбора переходов нет.
Условия проверяют наличие приложения или сайта в настройках либо включение ИИ.
Они не проверяют, запущено ли приложение.

**↶ / ↷**, **Ctrl+Z / Ctrl+Y** отменяют и повторяют перемещения, вставки,
удаления и изменения параметров. Удаление условия удаляет и его вложенные блоки;
это изменение также можно отменить. История изменений сохраняется после кнопки
**Сохранить**, но сбрасывается при открытии другого сценария.

Колесо прокручивает поле, **Ctrl+колесо** и кнопки **− / +** меняют масштаб.
Перетаскивание фона левой или средней кнопкой перемещает рабочую область.
**Вместить** показывает весь сценарий. При первоначальном открытии небольшого
сценария масштаб подбирается под доступный размер; большие сценарии можно
просматривать панорамированием или уменьшением масштаба.

**Проверить** проверяет схему без выполнения действий. **Запустить** выполняет
текущий черновик, даже если он ещё не сохранён, и выделяет текущий блок.
**Остановить** передаёт отмену текущему действию и прерывает ожидание.
Уже выполненные действия не откатываются. Во время запуска редактирование
заблокировано. **Сохранить** сохраняет сценарий для запуска голосовой фразой
или текстом. Флажок **Запуск по фразе** не ограничивает ручной запуск черновика.

Произвольный старый граф с пересекающимися ветками, несколькими завершениями
или неподключёнными блоками не преобразуется автоматически: конструктор покажет
сообщение, а исходный сценарий останется в файле без изменений. Обычные цепочки
и условия с общим продолжением открываются без изменения поведения.

## Совместимость данных

У `AssistantScenario` появилось необязательное поле `Flow`. Если оно отсутствует,
старый список `Commands` исполняется прежним способом. В редакторе старый сценарий
показывается цепочкой текстовых блоков без автоматической записи файла. При
явном сохранении добавляется `Flow`; исходные `Commands`, ID и флажок `Enabled`
сохраняются. Если `Flow` задан, именно он используется для выполнения. Старую
версию программы не следует использовать для редактирования новых схем.

Текстовый блок сохраняет прежнюю маршрутизацию, включая сценарии и настроенный
ИИ fallback. Обычный блок действия вызывает конкретный зарегистрированный
контракт напрямую и не обращается к планировщику. Постепенно заменяйте текстовые
блоки на действия. Неизвестное действие или выключенный плагин остаётся в
черновике вместе с аргументами, но блокирует сохранение и запуск до исправления.
Неизвестная версия схемы отклоняется без понижения версии или перезаписи файла.

## Формат и ограничения схемы

`ScenarioFlow(Version, EntryNodeId, Nodes)` хранит узлы со стабильными GUID.
`Next` и `Otherwise` — ссылки на узлы, а не номера в интерфейсе. В узле действия
хранятся `ActionId` и `Arguments`. Аргументы кодируются строками; тип и диапазон
проверяются по `ActionParameterDescriptor.Kind`, `Minimum`, `Maximum`, `MaxLength`
и `AllowedValues`. Пустой allowlist запрещает все значения.

Версия 1 допускает от 2 до 32 узлов, один старт и хотя бы одно завершение.
Запрещены циклы, недостижимые узлы, неизвестные типы, повторные ID и ссылки на
отсутствующие узлы. Каждая пауза длится 1–30 секунд; сумма пауз во всех ветках —
не более 120 секунд. Весь граф и аргументы всех веток проверяются перед первым
действием. Исполняется снимок проверенной схемы. Доступность и аргументы действий
повторно проверяются непосредственно перед каждым вызовом. При первой ошибке
сценарий останавливается.

## Общий контракт действий

Контракты находятся в `Egorik.Core.Actions`:

- `IAssistantActionProvider` — версия API и набор доступных действий поставщика;
- `AssistantActionDescriptor` — стабильный ID, название, описание, риск и поля;
- `ActionParameterDescriptor` — тип, обязательность, ограничения и подписи значений;
- `ActionInvocation` — ID действия и значения аргументов;
- `IAssistantActionRegistry` — локальный каталог, валидация и выполнение.

ID действия имеет пространство имён поставщика, например
`builtin.application_open` или `applications.yandex_music.set_volume`.
Версия API поставщика должна точно совпадать с `AssistantActionRegistry.ApiVersion`.
Повторные ID и чужие пространства имён отклоняются при регистрации. Каталог
действий вычисляется заново, поэтому изменения настроек и отключение плагина
учитываются без сохранения устаревших разрешений. Редактор обновляет варианты
после сохранения настроек.

В прототипе подключены адаптеры существующих безопасных реализаций, интеграций
приложений и декларативных плагинов. Для автоматического сценария разрешены
только действия с `CommandRisk.Low`. Реестр сценариев отделён от списка
ИИ-инструментов: регистрация действия не добавляет его в ИИ-планировщик.
Порядок «сценарий → базовая команда → ИИ fallback» сохранён.

## Расширение и будущие плагины

Новый доверенный адаптер реализует `IAssistantActionProvider`, публикует
`ActionProviderManifest` версии 1 и регистрируется явно в `Bootstrapper.cs`.
Ему передаются узкие зависимости через конструктор. Повторная проверка бизнес-
ограничений остаётся в реализации действия. Плагину не передаются DI-контейнер,
shell, произвольный путь, URL или системные API.

Внешние DLL по этому контракту не загружаются. Контракт поставщика не является
песочницей или системой выдачи разрешений. Будущий загрузчик должен отдельно
проверять совместимость, предоставлять изолированное исполнение и контролировать
подтверждённые разрешения. До этого подключаются только известные адаптеры хоста.
Адаптер декларативных плагинов проверяет включение плагина, объявленную capability,
наличие локального обработчика низкого риска и выбранную сущность из каталога.
JavaScript-плагины не получают автоматический экспорт действий. Текущий Dota-
плагин использует обработчик среднего риска и остаётся доступен через прежние
команды, а не как новое автоматическое типизированное действие.

## Проверка тестовой сборки

Если Debug-версия открыта и удерживает DLL, используйте отдельную конфигурацию
на уровне проектов (решение объявляет только Debug и Release):

```powershell
dotnet restore Egorik.slnx
dotnet build src/Egorik.App/Egorik.App.csproj --no-restore -c FlowTest
dotnet test tests/Egorik.Core.Tests/Egorik.Core.Tests.csproj --no-restore -c FlowTest
dotnet test tests/Egorik.App.Tests/Egorik.App.Tests.csproj --no-restore -c FlowTest
dotnet format Egorik.slnx --verify-no-changes --no-restore
dotnet run --project src/Egorik.App/Egorik.App.csproj --no-build --no-restore -c FlowTest
```

Тестовая сборка использует те же пользовательские настройки, что и обычная.
Для проверки настоящего голосового сценария запускайте одну версию приложения,
чтобы два процесса не конкурировали за микрофон.
