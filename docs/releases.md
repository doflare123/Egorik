# Подготовка релиза

## Сборка Windows x64

Нужны Windows x64, .NET 10 SDK и доступ к NuGet при восстановлении пакетов.
Из корня репозитория:

```powershell
dotnet restore Egorik.slnx
dotnet build Egorik.slnx -c Release --no-restore
dotnet test Egorik.slnx -c Release --no-build --no-restore
dotnet format Egorik.slnx --verify-no-changes --no-restore
./scripts/Publish-Release.ps1
```

Версия берётся из `Directory.Build.props`. Для v0.1 используется версия
сборок `0.1.0`. Результаты:

- `artifacts/releases/Egorik-0.1.0-win-x64.zip`;
- `artifacts/releases/Egorik-0.1.0-win-x64.zip.sha256`.

Скрипт каждый раз публикует в новый каталог `artifacts/staging`, проверяет
наличие exe, .NET, нативных голосовых библиотек и встроенного плагина, затем
упаковывает папку и вычисляет SHA-256. Старые staging-каталоги можно удалить
после проверки релиза. `artifacts` исключён из Git.

Профиль `WindowsPortable` включает .NET в поставку. Trimming и single-file
отключены для сохранения совместимости Avalonia, WinRT и нативного голосового
стека. Распространяйте весь ZIP, а не отдельный exe. Модели, ключи, настройки
и журналы пользователя в сборку не копируются.

## Ручная проверка архива

Перед публикацией распакуйте ZIP в новую папку, желательно на машине без .NET:

1. Запустите `Egorik.exe`, проверьте первый запуск и текстовые дату/калькулятор.
2. Скачайте модель Vosk явной кнопкой, проверьте микрофон и голосовую команду.
3. Проверьте нейроголос после отдельной загрузки и резервный системный TTS.
4. Отключите прослушивание и проверьте освобождение аудиоустройства.
5. Проверьте скрытие в tray, повторное открытие и «Полный выход».
6. Проверьте сохранение настроек после перезапуска и наличие встроенного плагина.

## GitHub Releases

После коммита и отправки подготовленных файлов создайте и отправьте тег:

```powershell
git tag v0.1
git push origin v0.1
```

Workflow `Windows release` проверит решение, соберёт архив и создаст **черновик**
GitHub Release с ZIP, SHA-256 и описанием из `CHANGELOG.md`. Проверьте вложения
и опубликуйте черновик в GitHub. Повторный запуск для существующего релиза не
перезаписывает его автоматически. Ручной запуск workflow создаёт только artifact.

Можно создать релиз вручную через страницу Releases репозитория, выбрав тег
`v0.1` и прикрепив оба файла из `artifacts/releases`. Бинарные файлы не нужно
коммитить в исходный код.
