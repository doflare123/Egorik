# Интеграции приложений

Egorik не управляет произвольным активным окном. Работа с каждой программой
проходит через локально зарегистрированный адаптер с конечным каталогом действий.
Так модель может предложить `steam.launch_game`, но не может отправить произвольную
клавишу, путь, командную строку или клик.

## Контракты

`IApplicationIntegration` публикует `ApplicationIntegrationDescriptor` и
исполняет `ApplicationActionRequest`. Дескриптор действия содержит:

- стабильный `snake_case` ID;
- пользовательское название и описание;
- точный набор параметров;
- обязательность, максимальную длину и allowlist значений параметров;
- `CommandRisk`;
- `IsAvailableToAi`, который по умолчанию равен `false`.

`ApplicationActionRegistry` строится в Core и до вызова адаптера проверяет ID,
риск, неизвестные/лишние аргументы, обязательность, длину, управляющие символы и
allowlist. Адаптер обязан повторить проверки, от которых зависит его безопасность.

## Как добавить программу

1. Реализовать `IApplicationIntegration` в `Egorik.Infrastructure/Applications`.
2. Описать только конкретные действия программы. Не добавлять универсальные
   `click`, `type`, `run`, `open_path`, `send_keys` или подобные операции.
3. Выполнять действие через существующий платформенный интерфейс или добавить
   новый узкий интерфейс в Core.
4. Оставить `IsAvailableToAi: false`, пока действие не доказано низкорисковым и
   не имеет полностью проверяемых аргументов.
5. Зарегистрировать адаптер как `IApplicationIntegration` в `Bootstrapper.cs`.
6. Для точной локальной фразы добавить сопоставление в
   `ApplicationActionCommand`; побочный эффект остаётся только в `ExecuteAsync`.
7. Добавить тесты успешного действия, ложного срабатывания и отклонения лишних,
   неизвестных и запрещённых значений.

Низкорисковые действия с нулём или одним текстовым параметром могут публиковаться
ИИ через `ApplicationActionAiTool`. Более сложное действие получает отдельный
узкий `IAiTool`, как поиск по разрешённой книге Excel. Даже такой инструмент
повторно проходит через `ApplicationActionRegistry`.

## Границы текущей версии

Механизм подтверждения средне- и высокорисковых действий пока не реализован.
Поэтому адаптеры не должны автоматически изменять существующие документы,
удалять данные, устанавливать программы, работать с произвольными путями или
вводить текст в неизвестное окно. Для таких возможностей сначала нужен отдельный
одноразовый запрос подтверждения с неизменяемым описанием действия и сроком
действия, а уже затем — узкий адаптер.

Создание заметки Word является безопасным исключением для базовой команды: Egorik
создаёт новый уникальный `.docx` только в собственном каталоге данных, не принимает
путь и не перезаписывает существующий файл. Эта операция не публикуется ИИ.

## Названия и голосовые ошибки

Склонения и одна ошибка распознавания допускаются только при сравнении с уже
зарегистрированным псевдонимом приложения, сайта или игры. Например, настроенное
имя `музыка` совпадает с `музыку` и `музыке`, а `стим` — с распознанным `стиле`.
Глагол действия и структура команды остаются точными: нечёткое сравнение не
применяется ко всей фразе и поэтому не превращает случайную речь в команду.

Для Steam сначала читаются только установленные `appmanifest_*.acf`. Название
команды сравнивается с этим конечным каталогом; латинское `Dota 2` может быть
сопоставлено с русскими формами `дота 2` и `доту`. Если лучший результат не
единственный, игра не запускается и ассистент просит уточнение.

## Яндекс Музыка для Windows

Адаптер ищет точный файл `Яндекс Музыка.exe` среди запущенных процессов, в
Windows App Paths и на один уровень ниже `%LocalAppData%\Programs`. Поэтому в
настройке достаточно `музыка=Яндекс Музыка.exe`; жёстко прописывать каталог
конкретной версии не требуется.

Если Яндекс Музыка уже работает, команда открытия показывает её существующее
окно, в том числе скрытое в tray, без повторного запуска exe. Если окно ещё
загружается, Егорик просит повторить команду. При первом запуске используется
найденный exe с рабочим каталогом приложения. Поиск и Моя волна передаются через
зарегистрированный в Windows протокол `yandexmusic://`, без ручной передачи URL
в аргументах exe. Пауза, продолжение и переключение
треков выполняются через Windows Global System Media Transport Controls после
выбора сессии с идентификатором Яндекс Музыки. Команда не отправляется текущему
активному окну или произвольному медиаплееру.

Команды «сделай музыку тише», «музыку погромче», «выключи звук в музыке» и
«установи громкость музыки на 40 процентов» меняют только Windows-аудиосессии
процессов установленного `Яндекс Музыка.exe`. Это отдельная громкость приложения
в микшере, не общая громкость колонок и не внутренний ползунок плеера.
Шаг изменения — 10 процентных пунктов; абсолютное значение — целое число 0–100.
Если аудиосессия ещё не появилась, ассистент просит включить трек и повторить
команду. На системную громкость он не переключается. Фразы без адресата,
например «сделай тише», остаются командами общей громкости.

ИИ может предложить только зарегистрированные действия `volume_up`,
`volume_down`, `mute`, `unmute` и `set_volume`. Для `set_volume` проверяется
единственный аргумент `percent` с allowlist строк от `0` до `100`.

## Память голосового контура

На время голосового ответа приостанавливается только захват микрофона; модель
Vosk и распознаватель не создаются заново после каждой команды. Нейросинтезатор
Sherpa-ONNX освобождается сразу после воспроизведения ответа. Полное выключение
голосовой активации по-прежнему освобождает микрофон, распознаватель и модель
Vosk.

Завершённые фрагменты Vosk объединяются после паузы, но их предварительный текст
сразу передаётся индикатору обращения. Поэтому рамка появляется после
распознавания имени и остаётся видимой при ожидании продолжения команды.
